# SFRA 扫频使用说明

日期：2026-10-28（2026-10-29 更新：**已不用上位机 GUI**，看下面这一节）

---

## ★ 现状（2026-10-29）：不用串口，CCS 里触发 + 内存导出

串口链路（CH340 / SFRA GUI）已整体关闭，`SFRA_GUI_ENABLE = 0`。
所以下面第五、六节讲 GUI 的部分**只作历史参考**，实际流程是：

1. **Rebuild All → Load & Run**（当前是纯 RAM 版，链接脚本 `28035_RAM_lnk.cmd`，
   `SFRA_FLASH_BUILD = 0`；掉电就要重下）
2. 不用手写任何变量：`SFRA_AUTO_START = 1`，上电 **2 s 后自动开扫**
   （延时是为了等 RefRamp 软启动 500 ms 爬完）
3. 扫频参数在 `APP/sfra_cfg.h`：**100 点，100 Hz ~ 5 kHz，step 1.040307**
   - 每点固定 65536 个中断 / 20 kHz = **3.28 s**，100 点约 **328 s**
   - 5 kHz = **fs/4**，必须做零阶保持(ZOH)校正才能用（见第六节的表和图）：
     相位 `+180*f/fs` 度（5 kHz 差 45°）、幅值 `+20log10|sinc(f/fs)|`（5 kHz 差 0.91 dB）
   - 可信度：**≤2 kHz 可信；2~3 kHz 尚可；4~5 kHz 只看趋势**（20 kHz 开关纹波会混进
     测量，这部分误差公式去不掉）。30 kHz 在 20 kHz 开关频率上物理不可测
     （Nyquist 10 kHz），要更高只能提 fsw
4. 进度：`SFRA1.FreqIndex` 0→100，`SfraDone` 变 1 即完成
5. 导出：`View → Memory Browser` → `&FreqVect`（32-bit Float）、
   `&OL_MagVect` / `&OL_PhaseVect` / `&Plant_MagVect` / `&Plant_PhaseVect`
   （32-bit Signed Int）→ `Save Memory` → TI Data (*.dat)
6. 换算：**全部 ÷ 65536**（见第六节），或直接用模板
   `docs/sfra/SFRA结果换算模板.xlsx`（内置公式 + 幅频/相频图，粘贴即可）

想再扫一遍：程序运行中在 Expressions 里写 `SfraTrig = 1`；
要关掉自动扫：`sfra_cfg.h` 里 `SFRA_AUTO_START = 0`。

---
适用工程：`SPI_LC_iq`（F28035 单相离网逆变，20 kHz 开关频率）

## 一、两种模式，编译期二选一

| | OLED 版 | SFRA 版（现在用这个） |
|---|---|---|
| `SFRA_ENABLE` | `0` | `1` |
| `SFRA_GUI_ENABLE` | `0` | `0`（不接上位机；要用才置 0→1） |
| `SFRA_FLASH_BUILD` | `0` | **`0`**（纯 RAM 运行，掉电丢失） |
| 链接脚本 | `28035_RAM_lnk.cmd` | **`28035_RAM_lnk.cmd`** |
| 程序在哪运行 | SARAM | SARAM |
| 显示 | OLED 8 行 | 无 |
| 示波器 `ScopeIout/ScopeIL` | 用（512 字） | **裁掉**（`SFRA_ENABLE==0` 才编译，省 512 字给结果数组） |

### 切换步骤

1. 改 `APP/dcac_cfg.h` 里两个宏：`SFRA_ENABLE`、`SFRA_FLASH_BUILD`
2. CCS 里：Project → Properties → Build → C2000 Linker → File Search Path，
   把 **Linker command file** 在 `28035_RAM_lnk.cmd` / `28035_FLASH_lnk.cmd` 之间换
3. **Rebuild All**（不能只 Build，宏改了要全编）
4. **Load Program**，然后 Reset + Resume

> **2026-10-29 更新**：SFRA 版现在也能用 RAM 脚本了 —— 串口协议整块关掉、
> 示波器缓冲裁掉之后，100 点的 5 个结果数组（1000 字）也放得下。
> 早先"`SFRA_ENABLE=1` + RAM 脚本会链接溢出"的说法只对**带 GUI 通讯**的老配置成立。
> 真溢出时的报错长这样：`FAILED TO ALLOCATE` 或
> `placement with alignment/blocking fails for section ".xxx"`。

## 二、扫什么，靠 `LOOP_MODE` 决定

改 `APP/dcac_cfg.h` 的 `LOOP_MODE`，Rebuild All。

| `LOOP_MODE` | 物理状态 | 注入 | 采集 | 用来测 |
|---|---|---|---|---|
| `LOOP_SINE_OPEN` (0) | 正弦开环 + 软启动 | 无 | 无 | **正常逆变运行**（不扫频）|
| `LOOP_VOLT_CLOSED` (1) | 电压单环（电流环旁路，PR 输出直当调制比） | `Vref` | `IRef`→`Vout` | 电压环闭环增益 |
| `LOOP_CURR_CLOSED` (2) | 电流单环（电压环旁路） | `Iref` | `Mod`→`IL` | 电流环闭环增益 |
| `LOOP_DUAL` (3) | 电压 + 电流双环 | `Vref` | `IRef`→`Vout` | 双环下电压环增益 |
| `LOOP_FIXED_DUTY` (4) | 固定占空比开环 | `Duty` | `Mod`→`IL` | **受控体 Plant** |

采集点说明：`SFRA_IQ_COLLECT(control_output, feedback)` 的第一个参数必须是
**受控体的输入**（电压环就是 PR 的输出 `IRef`，不是被注入的 `PR_V.Ref`），
否则算出来的是闭环增益 Y/R 而不是受控体。

**测受控体（第一步）用 `LOOP_FIXED_DUTY`**，测环路增益用 1/2/3。

## 三、扫频时的直流工作点

单相逆变器的参考是 50 Hz 正弦，没有稳态工作点，所以 `SFRA_ENABLE=1` 时
参考被**冻结成直流**：

| 量 | 值 | 宏 |
|---|---|---|
| 电压环给定 | 20 V | `SFRA_VREF_DC` |
| 固定占空比 | 0.4 | `SFRA_DUTY_DC` |
| 电流环给定 | 1 A | `SFRA_IREF_DC` |

都在 `APP/sfra_cfg.h` 里改。

## 四、扫频参数

```c
SFRA_FREQ_LENGTH   48          /* 48 点：100 Hz ~ 2.1 kHz */
SFRA_FREQ_START    100.0f      /* 起始 100 Hz */
SFRA_FREQ_STEP     1.059253f   /* 每十倍频程 40 点 */
SFRA_ISR_FREQ      20000.0f    /* = 开关频率，填错频率轴整体偏移一倍 */
```

**上限不能超过 `fsw/10 ≈ 2 kHz`**。想再多扫几个点可以改成 60 点（到 3 kHz），
但 100 点（31 kHz）已经远超声速采样限制，高频段全是假数据。

## 六、CCS 里看数据（不用 GUI 也行）

扫完以后数组里就有结果，Expressions 里加：

| 数组 | 内容 | 原始格式 | 真实值 = |
|---|---|---|---|
| `FreqVect` | 频率 | **float32** | 原样（Hz） |
| `Plant_MagVect` | 受控体幅值 | int32 = dB × 65536 | `raw / 65536`（dB） |
| `Plant_PhaseVect` | 受控体相位 | int32 = 度 × 65536 | `raw / 65536`（度） |
| `OL_MagVect` | 开环增益幅值 | int32 = dB × 65536 | `raw / 65536`（dB） |
| `OL_PhaseVect` | 开环增益相位 | int32 = 度 × 65536 | `raw / 65536`（度） |

> **标度依据**（反汇编 `SFRA_IQ_Lib.lib` 的 v1.20 IQ 版确认）：
> 幅度算完乘 `0x08AF96 = 569238 = (20/ln10) × 65536` → 结果就是 dB；
> 相位算完乘 `0x394BB8 = 3754936 = (180/π) × 65536` → 结果就是度。
> 所以是 **Q16 物理量**，除以 65536 即可，**不要再取 log10**。

**再做零阶保持校正**（占空比每 50 µs 才更新一次，相当于 ZOH）：

| 频率 | 保持相位滞后 | sinc 幅值衰减 |
|---|---|---|
| 1 kHz | 9° | −0.04 dB |
| 2 kHz | 18° | −0.14 dB |
| 3 kHz | 27° | −0.32 dB |
| 4 kHz | 36° | −0.58 dB |
| 5 kHz | **45°** | **−0.91 dB** |

```
幅度校正 = 换算值 - 20*LOG10(ABS(SIN(PI()*f/20000)/(PI()*f/20000)))
相位校正 = 换算值 + 180*f/20000
```

模板 `docs/sfra/SFRA结果换算模板.xlsx` 的 J~M 列已经内置这两个公式，图也用的是校正后数据。
> （更老的文档说"幅值 Q24、1.0=0dB、要 20log10(x/2^24)"是另一个库版本的说法，本工程不适用。）

## 七、电流内环已改成电感电流

`PI_I.Fdb = IL`（原先是 `ICap = IL - Iout`，两路相减噪声叠加）。

**注意**：`IL` 含 20 kHz 开关纹波，按 SFRA 规范**不能在 ISR 里做软件滤波**再喂给库，
否则会引入相移、模型失真。噪声只能靠硬件 RC 处理。

## 八、保护

`SFRA_ENABLE=1` 时 `Protect_Enable` **强制为 1**，且有 `#error` 互锁——就算用
`-dProtect_Enable=0` 硬覆盖也编不过。

真实阈值（按代码，不是按设计意图）：

| 保护 | 阈值 | 在哪 |
|---|---|---|
| **硬件 COMP1 + Digital Compare → TZ** | **10 A** | `protect.h` 的 `Trip_Amps_Default` |
| 软件过流 | 25 A | ISR 判断 |
| 软件过压 | 45 V（峰值） | ISR 判断 |

也就是说**第一道过流保护是硬件 10 A**，软件 25 A 只是兜底。

注入有故障门（`SFRA_INJ` / `SFRA_COL`），保护一动作就停止注入并清 `SFRA1.start`，
避免把故障期的数据当扫频结果。

## 九、内存（Flash 版实测，随 `LOOP_MODE` 略有变化）

```
FLASHA    0x1E48 / 0x1F80   代码（满了会自动 spill 到 FLASHC）
FLASHC    0x0000 / 0x2000   备用 8K 字
dataRAM1  0x0631 / 0x0C00   普通数据
SFRA_DATA 0x0020 / 0x0400   库内部状态段，0x9C00 起
```

`SFRA_IQ_Data` **必须 64 字对齐**。链接脚本里已经写了 `ALIGN(64)` 并单独划
`SFRA_DATA : origin = 0x009C00`（0x9C00 ÷ 64 = 624）。改脚本时这一步别删。

## 十、已知限制

1. OLED 和 SFRA 不能同时用（GPIO28/29 冲突）
2. Flash 版**只靠调试器 Load**，不要求脱机上电自启动（boot 引脚没动）
3. `LOOP_MODE` / `SFRA_ENABLE` / `SFRA_FLASH_BUILD` 都是**手改头文件**，
   没有做成 CCS build configuration（避免手改 `.cproject` 的风险）。
   配错组合的后果：`SFRA_ENABLE=1` 配 RAM 脚本会**链接溢出**，安全失败。
4. **`LOOP_CURR_CLOSED`（电流单环）必须带负载**：1 A 直流给定没有电压环兜底，
   轻载时会把输出电容充到 45 V 过压锁存。
5. 示波器用数组名寻址（`graphProp` 里已经是符号名），换模式后不用重填地址。
